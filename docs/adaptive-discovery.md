# 販売ページの発見と観測

店舗単位で一覧を共有し、1回の一覧取得で全ての有効な監視条件を照合する。商品詳細は既存の在庫巡回で取得するため、一覧の価格・在庫をそのまま通知しない。既存の個別検索は、一覧の掲載範囲外や別表記を補うため継続する。

## 初期の配分

|状態|一覧の間隔目安|期間・根拠|
|---|---:|---|
|通常|30分|まず観測を蓄積|
|変化が少ない店|60分|24回以上の成功、取得範囲で24時間以上追加なし|
|新しい対象ページを発見|10分|2時間。その後は自動で通常に戻る|
|短時間の販売終了が重なる店|10分|過去7日以内に販売時間の上限15分以内を2回観測。24時間限定|

重点枠は最大3店。発見した新規ページと購入不可→購入可能へ変化した商品は最大5ページ、30分だけ詳細確認を優先し、最短2分。初回の既存ページ取り込みでは重点監視しない。通信予算によって実際の確認は延びる。

一覧は毎回先頭を確認し、追加1ページだけで別表記・続きのページを交代で調べる。店舗が公開している `/new` の「新着商品」リンクと「新着順」リンクを発見した場合だけ採用する。確認していないソート引数を推測しない。1回は最大4通信（転送を含む）、後方探索は最大20ページ。ログに読んだ範囲・続きの有無・上限・失敗を残し、全店の全商品を網羅したとは扱わない。

自動監視の発見用通信は店舗一覧2600回/日、補完検索1400回/日。既知商品の目安8000回/日を含め、従来の全端末共通の自動監視12000回/日・同一店2000回/日の制限も継続する。重点商品は同じ枠の中で配分する。403・429・通信枠の制限は待機し、回避しない。一覧解析失敗だけでは既知商品の在庫巡回を止めない。

## 記録と推定の限界

- `target.discovery.firstSeenAt` は監視が初めて見つけた時刻。実際の掲載開始は不明なので `publicationAt:null`。
- `availabilityTiming` に最初の購入可能確認、最後の購入可能確認、その前後の購入不可確認を保持。
- 販売時間の下限は「最後の購入可能－最初の購入可能」。上限は「購入不可になった確認－購入可能になる直前の購入不可確認」。直前の購入不可がなければ上限は不明。
- 初回から売切、取得失敗、長い観測間隔を短時間完売の根拠にしない。観測間に始まり終わった販売は発見できない。30分で観測すれば全ての争奪戦に間に合う、とは保証しない。
- `discovery.log` は最大1000件・14日。既存の inventory-sync が観測日ごとの `discovery-logs/YYYY-MM-DD.jsonl` へ重複を除いて保存する。取得再開時も日時・店舗・商品・種類で照合して追記し、同時刻の別店舗を落とさない。

通常税込定価105%、通常ポケカ30th BOXのみ200%、商品別の上限、送料別、未知の定価の通知保留、送信済みID、停止設定を引き継ぐ。状態は既存の保存領域に gzip 形式で保持し、追加の自動実行サービスや保存領域は作らない。

## 検証

2026-10-04取得の実店舗の商品名・新着リンクを回帰入力に保存。通常/重点/静かな店への遷移、2回の短時間販売、観測不足、403/通信枠、掲載の部分失敗、先頭と後方の併用、価格条件・送信済みID・停止設定の保持を検証する。本番の保存先エラー中は、本番での周期・通知成功を確認済みと扱わない。

65ページ・38弾の保存済み状態を使い、外部接続なしで24時間を再現した検証では、一覧1632通信＋補完1056通信＋商品5326通信＝8014通信、圧縮状態は最大74500バイト・1チャンク、状態保存12435行だった。目覚ましと通信枠記録を足した推計は約34223行。これは模擬条件の値であり、本番の課金・アカウント全体の使用量や復旧を保証する数値ではない。送信済みIDと価格条件の保持も確認した。
