# 監視対象のON／OFFと価格・在庫履歴（v0.9.0）

## 操作

- 登録フォームの「この商品の対象店舗を選ぶ」で、商品ごとの対象店舗を選択できる。最低1店舗必要。
- 「店舗ごとの監視ON／OFF」は、その監視用合言葉の保存領域内の全商品に適用。OFFの店舗は掲載検索と商品ページ確認を停止する。
- 「商品ページのON／OFF・価格と在庫の履歴」から個別ページを停止・再開する。再発見・店舗再開・条件再開で、個別のOFFを勝手に解除しない。
- 個別ONでも店舗・条件・全体がOFFなら停止状態を表示。上限待機も別の状態として表示する。
- OFFでは履歴・通知済み情報を保持し、送信待ちの通知を取り消す。停止した対象を負荷計算から除外する。失敗時の待機時間や共有の接続制限は再開時も維持する。
- 停止ページも保存件数上限の50件に含む。監視条件を削除し、どの条件からも参照されなくなった商品ページは履歴も削除する。

## 記録する内容

各ページの監視取得で正常に確認できた価格・在庫と確認時刻を保存。同じ値が続く場合は初回時刻・最終時刻・確認回数をまとめる。値下げ、在庫変化、取得失敗、通信上限の待機、監視停止・再開の前後は分ける。

確認していない期間の連続在庫や実際の入荷・売切時刻は推測しない。旧版の最終価格から過去の履歴を作らない。初回は機能追加後の実際の取得から記録する。

各ページ最大100件。最後の記録が30日より前の行を表示・次回記録の際に除外する。繰り返し確認している同一値の行は、最初の記録が30日より前でも最終確認時刻を更新して残る。価格不明や条件付き価格も明記する。

大量の履歴は開いた商品の分だけ描画し、30秒ごとの画面更新でも開閉状態を保持する。移行用の書き出しには店舗OFF・ページOFF・履歴を含む。Node.js移行・再起動でも保持される。

## 検証

全141テスト成功。追加検証では、店舗OFFでの商品確認・掲載検索・通知停止、個別OFFの永続化、追跡用引数付きURLの詳細取得除外、負荷計算、不正操作、値下げ・在庫変化、失敗による履歴の分断、通知の重複防止、100件・30日の保存上限、表示時の文字列処理を確認。移行サーバーの既存テストにもON／OFFと履歴の引き継ぎを追加。
