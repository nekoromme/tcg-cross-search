# 検索速度の改善（2026-09-22 / v0.8.1）

## 原因と対応

- 店舗単位の同時実行枠を、APIの1回の取得ごとのFIFOキューに変更。追加確認の多い店舗が、未着手店舗の開始を塞がない。同時API取得数は6のまま。同じ店舗の続きは順番に処理する。
- 詳細確認を4商品ずつ続ける際に毎回取り直していた候補一覧を、同じ検索の続きだけ最長2分引き継ぐ。商品詳細の価格・在庫確認は省略しない。別条件・期限切れ・保存失敗の場合は通常の一覧取得に戻る。新規検索では引き継がない。
- Dayyaの独立した2種類の新品カテゴリ取得を並行化。片方が確認できない場合の未確認表示を維持する。
- 最初の結果の表示時間、全店の確認時間、各店の処理時間を表示する。

## 品質確認

- ローカルの全121テスト成功（既存114 + 新規7）。
- 13商品の継続確認の再現テストで、商品詳細の取得13回と全結果が一致。一覧取得を4回から1回に削減し、全取得は17回から14回に削減。
- 続きの商品詳細の価格変化、スコープ違い、期限切れ、保存失敗、別ページ、キューのエラー回復、同時実行上限、カテゴリ片側失敗を確認。
- 店舗数、確認対象商品数、追加ページ、タイムアウト、エラーと未確認の扱いは維持する。
