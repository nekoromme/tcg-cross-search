# 自動在庫監視 v0.8.0

2026-09-22。ユーザーから自動監視の実装を依頼されたため、従来の「定期監視は保留」を変更した。
抽選監視リポジトリとは独立した、販売在庫の監視機能。

## 使い方

1. 横断検索で商品名・ゲーム・価格条件を選び、「今の検索条件を監視登録」を押す。
2. 自動在庫監視の画面で条件を確認し、「この条件で監視を開始」を押す。
3. Discordへ通知する場合は「通知先と監視間隔」でウェブフックURLを保存し、テスト通知を送る。

直接 `/monitor.html` で条件を登録してもよい。検索結果から渡された商品は、初回の全店検索を待たずに商品確認を開始する。
ページを閉じてもCloudflare側で動く。スマートフォンのブラウザを常時開く必要はない。
通知先未設定でも確認と履歴記録は継続するが、外部通知は送らない。

## 監視と判定

- 初期60秒、30秒・3分・5分を選択可能。同じ店は最低30秒あけ、1巡1商品。最大6店舗を同時確認。
- 実行終了の30秒後に次の巡回。確認間隔は目標で、件数・通信時間・再試行により延びる。
- 新しい掲載の検索は別キュー。各条件・店舗で完了から30分あけ、1巡1店舗を順番に確認。混雑時は30分以上になる。
- 発見検索の続きは最大20バッチ。上限・取得失敗は画面に表示し、空結果を売切として扱わない。
- 最大10条件・100商品ページ。商品ページは条件間で共有し、同じページへの二重アクセスを避ける。
- 価格・在庫・商品名・販売単位を再取得してから通知判定。検索時の古い値は通知判定に使わない。
- 初回の購入可能状態、再入荷、価格条件内への値下がりを通知。予約を含めるか選択できる。送料は含まない。
- 0円・売切は購入不可。価格不明・税込価格不明・条件付き価格・通信失敗は未確認。
- 未確認で最後の確かな在庫状態を上書きしない。画面に取得失敗と過去の確認時刻を併記。
- 条件外が2回続くまで通知済み状態を解除しない。同じ商品の通知は最低5分あけ、同じ巡回で複数条件に一致しても1通知。
- 403・429はその店を30分休止。通常エラーも再試行間隔を延ばす。拒否の回避は行わない。

## 保存・通知・アクセス

Cloudflare Durable Objects（SQLite保存）に設定、確認状態、直近80件の通知履歴を保存。
ブラウザで作った256bitの合言葉のハッシュごとに保存領域を分離。合言葉は認証ヘッダーのみで送る。
別端末には同じ合言葉を入力する。合言葉を失うと元の監視領域を操作できないため、画面から表示して保管する。
合言葉の切り替えは元の監視の停止ではない。切替前に必要なら停止する。

Discord通知先はサーバー側に保存し、画面への読出し・書き出し・ログ・ソースには含めない。
通知内容は保存後に送信し、失敗時に最大5回再試行。売切になった通知や10分以上前の通知は送らない。
送信完了直後に実行環境が落ちる場合など、通知サービスをまたぐ完全な一度だけの配送は保証できない。
通知番号を含め、通常の繰り返し通知を状態保存で抑える。

Cloudflare無料枠は有限。アカウント全体の上限に達すれば停止・取得失敗になる場合がある。
有料プランへの変更や新しい有料契約はこの変更では行わない。
参考：[公式料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[公式の定期起動機能](https://developers.cloudflare.com/durable-objects/api/alarms/)。

## 有料サーバーへの移行

`src/monitor-core.js`（判定）、`src/monitor-engine.js`（巡回）、`src/monitor-service.js`（取得・操作）を共用。
移行先の起動コードは `scripts/monitor-server.mjs`。Node.js 24で実行でき、10秒の指定にも対応する。
10秒設定でも対象件数や通信時間による遅延はある。検索発見は引き続き低頻度。

1. 現在の監視画面で「全体を一時停止」。移行用データを書き出す。
2. 移行先へリポジトリを取得し、Node.js 24を用意する。
3. `deploy/monitor.env.example` を参考に、合言葉・保存先・必要なら通知先を環境変数へ設定。
4. 初回だけ `MONITOR_IMPORT_FILE` に書き出したファイルを指定し、`npm run monitor:server` を実行。
5. 状態と通知済み情報を引き継いで停止状態で起動する。画面で確認してから再開する。
6. `MONITOR_IMPORT_FILE` を設定から外し、再起動時の再取り込みを防ぐ。

Linux常駐サービス例は `deploy/tcg-monitor.service`。実際のNode.jsの場所・実行ユーザーに合わせる。
既定の待受は127.0.0.1:8787。外から使う時はHTTPSのリバースプロキシと公開URLの設定が必要。
保存先にはJSON状態と二重起動防止ロックを置く。書込みは一時ファイルへの同期保存後に置換する。
正常終了時はロックを消し、異常終了後は前のプロセスが存在しない場合だけ回収する。
この変更で移行先の購入や契約は行っていない。

## 検証

既存検索の回帰テストに加え、初回・再入荷・価格条件・未知状態・0円復帰・重複抑制・通知再試行・失敗時の休止・発見検索の続き・認証分離・永続保存と再起動・Nodeサーバーへの移行を自動検証する。
実環境の通知先は未設定なので、Discordの実配送は利用者が通知先を保存した後のテスト送信で確認する。
